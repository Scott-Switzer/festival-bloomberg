# Terminal Storage Role Audit V1

Classifies every table the terminal / OA touches into one of three roles and
records the boundary the serving-snapshot architecture enforces.

## Roles

| role | meaning | who writes |
| --- | --- | --- |
| `CANONICAL_EVIDENCE` | authoritative evidence, provider snapshots, identity, festival/tour graph, economics | acquisition + OA drivers |
| `SERVING_SYSTEM_DATA` | published copy of canonical + system alerts/read models | snapshot publisher (copy) + OA alert engine (on canonical, then published) |
| `WORKSPACE_USER_STATE` | watchlists, monitors, planning projects/shortlists/scenarios | the terminal only |

## Workspace tables (user state)

`core.watchlists`, `core.watchlist_items`, `terminal.saved_monitors`, and all of
`planning.*`. These exist in the dedicated `schema/workspace_schema.sql` — the
workspace DB does **not** apply the canonical migration stack, so evidence
schemas cannot accidentally appear there.

## System-data tables (stay on serving, NOT workspace)

`core.alerts` and `core.alert_related_entities` are SYSTEM DATA — generated by
the OA alert engine from evidence and consumed by `build_today` (which joins
them against the workspace watchlist in application code).

## Writes audited (post-PR37)

| object | writer | target role | fixed? |
| --- | --- | --- | --- |
| `core.watchlists` / items | terminal POST | WORKSPACE | yes |
| `core.watchlists` / items (default seed) | OA `_watchlists` phase | WORKSPACE | yes (was canonical) |
| `terminal.saved_monitors` | OA `_monitors` phase | WORKSPACE | yes (was canonical) |
| `planning.*` | terminal POST | WORKSPACE | yes |
| `core.alerts` | OA alert engine | SERVING_SYSTEM_DATA (via canonical) | correct as-is |

`migrate_workspace_state` is the only path that reads the deprecated canonical
copies of user-state tables (one-time import; canonical history is never
deleted).

## Enforcement

- `create_workspace_db` applies only `schema/workspace_schema.sql`.
- `open_serving_snapshot` opens the immutable snapshot read-only.
- The terminal never opens canonical at startup (`make_app`).
- `tests/python/test_terminal_serving_snapshot.py` asserts the workspace has
  user-state tables and does NOT contain canonical evidence tables, and that a
  separate process can write canonical while the terminal is online.
